CAPACIDADES IMPLEMENTADAS EN ESTA FASE
================================================================================

[A] BACKUP INSTITUCIONAL SEGURO
    - BackupService: generación de respaldos consistentes vía SQLite Online
      Backup API. Nunca copia en caliente con shutil.
    - Formato .bicu.bak: ZIP estándar con database.sqlite + manifest.json +
      signature.sha256.
    - Manifiesto con: backup_id, schema_version, SHA-256, row_counts, tablas,
      migrations_applied, python_version, platform.
    - Nombre de archivo: BICU_BACKUP_v{VERSION}_schV{SCHEMA}_{UTC}_{HASH6}.bicu.bak

[B] VALIDACIÓN DE BACKUP MULTICAPA
    - Nivel 1: Existencia del archivo.
    - Nivel 2: Integridad ZIP.
    - Nivel 3: Presencia de los 3 componentes (sqlite, manifest, signature).
    - Nivel 4: Hash SHA-256 (database.sqlite vs manifest vs signature.sha256).
    - Nivel 5: Cabecera SQLite válida (16 bytes mágicos).
    - Nivel 6: PRAGMA integrity_check.
    - Nivel 7: PRAGMA foreign_key_check.
    - Nivel 8: Tablas mínimas presentes (18 tablas obligatorias V001+).
    - Nivel 9: Compatibilidad de versión de esquema.

[C] RESTAURACIÓN CONTROLADA
    - RestoreService: flujo 8-etapas con confirmación explícita del operador.
    - Safety backup automático de la BD activa ANTES de cualquier reemplazo.
    - Reemplazo atómico con os.replace (mismo volumen).
    - Limpieza de archivos WAL/SHM residuales.
    - Fallback de recuperación si el reemplazo falla.
    - Post-verificación de la BD restaurada (integrity_check).

[D] SNAPSHOT PREVENTIVO
    - Todo proceso de restauración genera primero un snapshot de la BD activa.
    - El snapshot se deposita en {db_dir}/safety_snapshots/.
    - Si el snapshot falla, la restauración se cancela y los datos originales
      quedan intactos.
    - La ruta al snapshot se incluye en RestoreResult para el operador.

[E] PREFLIGHT OPERACIONAL
    - ReleasePreflightChecker: 5 grupos, 12+ verificaciones individuales.
    - Grupo 1: Ruta (OneDrive, local institucional).
    - Grupo 2: SQLite (cabecera, integrity_check, foreign_key_check).
    - Grupo 3: Esquema (schema_version, compatibilidad, migraciones pendientes).
    - Grupo 4: Patrimonial (32 registros históricos Matriz_5).
    - Grupo 5: Entorno (Python >= 3.9, SQLite >= 3.35).
    - Retorna PreflightReport con estado global y resumen de líneas para UI.

[F] TRATAMIENTO CORRECTO DE ERRORES DE INICIALIZACIÓN
    - El bloque except Exception: pass silenciado en app.py fue reemplazado por:
      * Logging estructurado en logger "bicu.startup".
      * messagebox.showwarning no bloqueante para el operador.
      * La ventana abre incluso ante error de migración, con advertencia visible.

[G] DECLARACIÓN CORRECTA DE DEPENDENCIAS
    - requirements.txt: agregado requests>=2.31,<3.0 (dependencia real del
      gemini_adapter.py existente desde Fase 29.x).
    - BICU_Consolidador.spec: actualizado con hiddenimports completos para:
      app.backup.*, zipfile, tempfile, traceback, logging, requests, urllib3.
